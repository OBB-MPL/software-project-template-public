# Ideen für spätere Versionen

Diese Datei sammelt unverbindliche Produktideen, Experimente und mögliche Funktionen für spätere Versionen.

Sie ist bewusst **kein Backlog und keine Aufgabenliste**. Eine Idee hier bedeutet weder Zusage noch Priorität noch geplanten Releaseumfang.

## Wann gehört etwas hierher?

Eine Idee gehört hierher, wenn sie:

- interessant erscheint, aber noch nicht ausreichend konkret ist
- möglicherweise erst in einer späteren Version relevant wird
- zunächst diskutiert oder bewertet werden soll
- noch keine Akzeptanzkriterien oder klare Umsetzung benötigt
- nicht verloren gehen soll, obwohl aktuell kein Issue sinnvoll ist

## Wann wird aus einer Idee ein Issue?

Eine Idee wird in ein GitHub Issue überführt, sobald sie konkret verfolgt werden soll und mindestens grob klar ist:

- welches Problem oder welchen Nutzen sie adressiert
- welches Ergebnis erwartet wird
- welche wesentlichen Randbedingungen gelten

Ab dann ist das Issue die verbindliche Quelle für die konkrete Arbeit. Die Idee kann aus dieser Datei entfernt oder mit einem Link auf das Issue als übernommen markiert werden.

## Wann gehört etwas in die Roadmap?

Die [Roadmap](roadmap.md) enthält größere Entwicklungsrichtungen, die grundsätzlich geplant oder gewünscht sind. Eine einzelne unreife Idee muss dort nicht erscheinen.

Der typische Weg ist:

**Idee → Bewertung → Roadmap und/oder GitHub Issue → Milestone → Umsetzung → Release**

Nicht jede Idee muss alle Stufen durchlaufen.

## Pflege

Die Ideensammlung gelegentlich überprüfen:

- überholte Ideen löschen
- ähnliche Ideen zusammenführen
- konkret gewordene Ideen in Issues überführen
- größere bestätigte Entwicklungsrichtungen in die Roadmap aufnehmen

So bleibt diese Datei ein leichtgewichtiger Ideenspeicher und wird nicht zu einem zweiten Issue-Backlog.
