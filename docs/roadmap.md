# Roadmap

Die Roadmap beschreibt die geplante Entwicklungsrichtung des Produkts. Sie ist bewusst gröber als GitHub Issues und enthält keine zweite operative Aufgabenliste.

## Zweck

Die Roadmap beantwortet vor allem:

- Welche größeren Produktstufen sind geplant?
- Welche Ziele oder Fähigkeiten sollen diese Stufen erreichen?
- Welche Themen sind bewusst noch nicht Teil des aktuellen Releaseumfangs?

Konkrete Umsetzung, Akzeptanzkriterien und Bearbeitungsstatus gehören in GitHub Issues. Der für einen Release verbindliche Umfang wird über Milestones festgelegt.

## Empfohlene Struktur

### Current

Aktueller Produktstand und das unmittelbar nächste Releaseziel.

### Next

Größere Themen, die nach dem aktuellen Release realistisch als Nächstes folgen sollen.

### Later

Langfristige, bereits grundsätzlich gewünschte Entwicklungsrichtungen ohne verbindlichen Termin.

## Abgrenzung zu Ideen

Noch unreife Einfälle, Experimente und mögliche spätere Funktionen gehören zunächst in [ideas.md](ideas.md). Erst wenn eine Idee ausreichend konkret und grundsätzlich verfolgenswert ist, wird sie in die Roadmap aufgenommen oder als GitHub Issue formuliert.

## Beispiel

### Current

- V0.8 stabilisieren
- Release-Blocker schließen

### Next

- V0.9 Release Candidate
- UI/UX konsolidieren

### Later

- native App
- zusätzliche Integrationen

Die konkreten Punkte dieses Beispiels nach dem Erstellen eines neuen Projekts entfernen und durch die tatsächliche Produkt-Roadmap ersetzen.
