# Sicherheit

## Geltungsbereich

Dies ist eine Projektvorlage ohne unterstützte Produktversionen oder zugesagte Reaktionszeiten. Im abgeleiteten Projekt unterstützte Versionen und einen tatsächlich erreichbaren privaten Meldeweg ergänzen, bevor externe Nutzer das Produkt einsetzen.

## Schwachstellen melden

Keine ausnutzbaren Details, Zugangsdaten oder personenbezogenen Daten in öffentlichen Issues oder Pull Requests veröffentlichen.

- Falls im Repository unter **Security → Advisories** die Option **Report a vulnerability** verfügbar ist, diesen privaten Meldeweg nutzen.
- Andernfalls einen bereits vereinbarten privaten Kontakt zum Repository-Verantwortlichen verwenden. Falls keiner bekannt ist, zunächst ohne technische Details einen privaten Meldeweg erfragen.

Eine Meldung sollte betroffene Version, Auswirkung und minimale Reproduktionsschritte enthalten. Sensible Belege nur über den vereinbarten privaten Kanal austauschen.

## Projektstart

Der Verantwortliche richtet einen privaten Meldeweg ein und dokumentiert unterstützte Versionen. Zugangsdaten gehören in geeignete lokale Konfiguration oder GitHub Secrets; Beispielkonfigurationen enthalten ausschließlich Platzhalter. Versehentlich veröffentlichte Zugangsdaten ersetzen bzw. widerrufen — bloßes Löschen aus der neuesten Dateiversion reicht nicht.
